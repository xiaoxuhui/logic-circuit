# 删除保存门测试报告

日期：2026-10-17（Asia/Shanghai）。

## 行为

“我的逻辑门”每一项增加独立删除按钮，桌面显示 ×，手机显示“删除”；右键条目也能删除。删除后从库中移除，计数与空态同步。已有画布实例及其他保存门内部引用继续工作，不连带拆除电路。支持撤销、重做、自动保存和导入导出。

内部实现为可选 hidden 布尔标记及引用保留：没有引用时真正清理定义；仍被引用时保存其实现；删除最后一个引用后清理不可达的隐藏定义。value、节点、导线和版本 1 格式保持兼容。

## 测试结果

- 新增核心测试在实现前：17 passed / 6 failed，失败包括缺少 deleteDefinition 和尚未拒绝非法 hidden 标记。
- 实现后 `node --test tests/core.test.cjs`：23 passed / 0 failed。
- `node --check src/app.js`：通过。
- `node scripts/build.cjs`：成功，输出 dist 四个资源文件。
- `node tests/browser.cjs`：47 passed / 0 failed；Chromium 151.0.7922.34，桌面 1440×1000，移动 390×844；pageerror 数 0。
- `git diff --check`：通过。

## 新增核心验证

1. 未使用的保存门真正移除，原始状态不被修改，元件和导线不变。
2. 已放置实例的实现被保留，全部 NAND 真值组合仍正确，存档校验通过。
3. 被其他嵌套门引用的定义保留，嵌套求值正确。
4. 删除未使用外层门时清理内部隐藏定义，其他可见门保留。
5. 删除最后一个画布引用后清理隐藏定义。
6. 旧定义无 hidden 字段可正常读取，非法非布尔 hidden 被拒绝。

## 移动修复与视觉检查

初次移动测试发现一次 tap 删除两条：pointerup 的即时激活移除了条目，浏览器后续兼容 click 命中下一条目。现在按触摸来源、位置和时间拦截该重复 click，保留独立的下一次触摸操作；I45 回归通过。

实际查看 tests/artifacts/desktop-library-delete.png 和 mobile-library-delete.png。删除按钮未嵌套在拖出按钮中，桌面与手机可见；移动端为独立的“删除”按钮。移动测试使用 Chromium 触屏模拟，未在实体手机测试。
