# 我的世界原版红石规则调研

2026-10-20。状态：调研完成，转换器修正待实现。此记录取代 B66 中把电路按红石风格示意绘制就视作转换完成的假设；B66 的既有测试只能证明示意图显示、飞行和快照正确，不能证明结构符合 Minecraft 放置或红石运行规则。

## 用户最新确认

- 拉杆改为右键操作，取代此前左键切换的要求。
- 一个拉杆仅表示一个比特；多位输入、输出、线路和延迟都必须逐位对应。
- 原版没有集线器、分线器方块。这些元件只能参与按位连接映射，转换后的方块结构中不得保留虚构元件或多位信号方块。
- 仍只观察，不导出；保留 WASD、空格、Shift 和鼠标视角。
- 每个方块位置必须明确：粉、火把、中继器及支撑块不能靠任意小数坐标、缩放或模型重叠假装为合法结构。

## 已核对的基础机制

1. **交互**：PC 默认使用/交互键是右键；拉杆输出开/关。数字电路中用一套拉杆和线路表达一个二进制位，不将 0–15 的红石信号强度混作多比特数据。
2. **粉线路与信号**：输出最大强度 15，红石粉逐段衰减；多个相连的粉属于一个电气网络，不能当作互不相干的交叉线。非预期相连会串线，必须在三维结构上分离，且验证相邻和台阶连接。
3. **支撑与高度**：本项目先使用完整实心支撑块。每个上方方块空间最多放置一份红石粉；上下线路通过合法的一格台阶连接，不能悬空、贴墙直上或直接用竖直模型条表示红石粉连接。台阶还需检查上方净空和遮挡，跨层线路要避免形成意外台阶连接。
4. **中继器**：从背面接收信号，正面输出；非零输入恢复为 15，四档分别为 1/2/3/4 红石刻。它具有方向、延迟、脉冲整形和侧面锁定规则，不能只是一个带标签的逻辑延迟方块。
5. **火把**：需要合法附着面；附着方块被供电时熄灭，否则点亮。输出不能回到自身附着块。典型非门是输入粉指向实心方块，火把附着于该方块顶部或另一侧，再从火把一侧引出输出。需要区分输入方块、附着方向、强/弱供电和输出位置。
6. **计时**：默认 20 游戏刻/秒，1 红石刻=2 游戏刻=0.1 秒。通常火把切换延迟为 1 红石刻，而不是 0.5 红石刻。中继器四档是 0.1/0.2/0.3/0.4 秒。若需要特殊半刻行为，必须注明对应版本和具体更新规则，不能混用单位。
7. **额外约束**：粉朝向/点状或十字形连接、强弱供电、短脉冲处理、火把烧毁、灯的熄灭延迟、更新顺序及 Java/基岩差异也会影响行为。不能据一个简化网页模拟器就宣称完整还原两种版本。

## 现有实现的差距与后续验收

现有 minecraft-model.js 使用小数坐标、长条粉模型和抽象端子；多位线路以 any-bit-high 表示，多位延迟只画一个中继器，集线/分线仍被画成组件。这些不能当作原版结构。当前仅完成查证与记录，未修改这些行为，未实现拉杆点击。

修正应依次通过：

1. 将所有层级连接规范化为单比特网络，消去集线/分线映射，验证补零、截高位及端口方向；16 位应有 16 个独立拉杆、灯和延迟通道。
2. 使用整数方块占用、合法支撑与真实门模板。验证一个方块空间不能同时放多个组件、火把附着面与取电块正确。
3. 生成不会意外并网的三维粉线路，验证每步连接高度/净空、跨线隔离、实际粉路径长度及中继器放置朝向。
4. 验证拉杆近端 15、逐段衰减、掉到 0 后不亮灯，中继器恢复至 15；补强后的额外延迟需要计入。
5. 右键命中对应拉杆只改变该比特，飞行/拖动/右键空白不误切换；状态传播须反映粉和中继器/火把机制，而不是直接把原逻辑门结果贴到灯上。
6. 原版没有与本游戏同步离散寄存器完全相同的单个中继器；若要保持原“下一步”时序，需要明确时钟与锁存结构，不能直接一换一并宣称等价。
